# Mobile web shell

How the page hosts the game. Owned by Build & Release — if a change here makes
gameplay awkward, say so rather than working around it.

## Scaling: RESIZE, in CSS pixels

`src/main.ts` uses `Phaser.Scale.RESIZE`. The canvas always equals the
viewport, so the game fills any phone screen exactly: no letterboxing, no black
bars, no surprise aspect ratio.

The trade-off is that there is **no fixed design resolution**. A scene cannot
assume 720x1280 and centre things against it — it has to lay out against
`this.scale.gameSize` and re-run that on resize. `BootScene.layout()` is the
pattern to copy:

```ts
this.layout();
this.scale.on(Phaser.Scale.Events.RESIZE, this.layout, this);
```

Rotation, the iOS URL bar collapsing, and the Android keyboard all arrive as
resize events. Handling resize is not optional.

### Why 1 canvas pixel per CSS pixel

In RESIZE mode Phaser sets the canvas backing store to the CSS size, so we
render at DPR 1 — on a 3x phone that is one third of the pixels. Two reasons to
keep it:

- It is the cheapest path to 60fps on mid-range Android. Rendering a Phaser
  WebGL scene at 3x is the most common cause of dropped frames on that hardware.
- Game coordinates stay in CSS pixels, which is one less thing for gameplay
  code to think about.

Vector shapes look slightly soft as a result. Raster art authored at 2x and
downsampled does not. **If the art ever demands sharper output**, the change is
to switch to `Phaser.Scale.NONE` and drive it manually:

```ts
const dpr = Math.min(window.devicePixelRatio, 2); // cap at 2 — 3x is not worth it
game.scale.setZoom(1 / dpr);
game.scale.resize(window.innerWidth * dpr, window.innerHeight * dpr);
```

That makes world coordinates device pixels, so every scene's layout maths
changes with it. Don't do it casually, and re-run the device test pass after.

## Safe areas

The page paints edge to edge (`viewport-fit=cover`), so the notch, the dynamic
island and the home bar all sit *over* the canvas. `src/viewport.ts` exposes
where it is safe to put things:

```ts
const safe = getSafeArea(width, height); // { x, y, width, height } in CSS px
```

Backgrounds can fill the whole screen. **Anything tappable, and anything the
player has to read, goes inside the safe rect** — a button under the iOS home
bar is a button that swallows taps as a system swipe.

`env(safe-area-inset-*)` is not readable from JS, so `viewport.ts` keeps a
hidden probe element whose padding comes from `env()` and reads the resolved
pixels back. That is deliberate; reading the CSS custom properties directly is
not reliable across browsers.

## Touch

- `touch-action: none` and `overscroll-behavior: none` in `src/styles.css` stop
  scrolling, pinch-zoom and pull-to-refresh inside the canvas.
- `user-scalable=no, maximum-scale=1` in the viewport meta is what removes the
  legacy 300ms tap delay on iOS Safari. `suppressBrowserGestures()` in
  `viewport.ts` adds belt-and-braces handlers for older iOS, which still fires
  `gesturestart` and double-tap zoom regardless of the meta tag.
- Use `pointerdown`, not `pointerup` or `click`, for anything that should feel
  instant.

## PWA

`public/manifest.webmanifest` plus the icons make it installable to the home
screen in portrait, standalone. Icons are generated by
`node scripts/gen-icons.mjs` from the same shapes as `icon.svg` — the PNGs are
committed, so only re-run it if the design changes.

`public/sw.js` is a ~40-line service worker: network-first for the HTML
document, cache-first for Vite's content-hashed assets. It is registered in
production only. **If you ever suspect you are looking at a stale build, open
the URL with `?nosw=1`** — that unregisters the worker and clears the caches.

## On-device FPS

Append `?fps=1` to any URL for a live FPS readout with a running minimum. That
is the number that goes in `docs/device-test-log.md`.
